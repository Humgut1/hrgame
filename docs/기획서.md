## 1. 제품 개요

HR 주니어와 취준생이 **실제 회사에서 일하는 것처럼** HR 의사결정을 연습하는 시뮬레이터.
MBA 모의경영의 HR 버전. 사내 메신저와 업무포털 환경에서 문제가 자연스럽게 도착하고,
회사 설정 데이터를 근거로 문제를 해결한다.

**핵심 원칙 3가지 (설계 시 항상 이걸로 판단할 것)**

1. 문제를 "출제"하지 않는다. 상황이 메신저로 도착할 뿐이다. 선택지 버튼 없음, 전부 자유 서술.
2. 정보는 항상 부족하게 시작한다. 되물어야 나온다. 좋은 질문을 했는지가 평가 대상.
3. 정답은 없고 트레이드오프만 있다. 모든 결정이 여러 지표에 동시에 반영된다.

## 2. 전체 구조

```
트랙: 채용 → 인사운영 → 보상 → 노무 → ER   (각 3~4 스테이지)
게임 루프: 인박스 수신 → 자료 조사 → NPC 협상 → 결정 제출 → 즉시 반응 → D+N 후속 → 신뢰도 갱신
```

- 초반 스테이지는 NPC 1~2명과만 소통. 후반으로 갈수록 인원과 도메인이 늘어난다.
- **신뢰도**는 NPC별 0~100으로 스테이지를 넘어 누적된다. 낮으면 다음 판에서 정보를 덜 준다.
- 클리어 조건은 점수 통과가 아니라 "이 사람이 다음에도 나와 일하고 싶어하는가".

## 5. 시나리오 상세 — 오퍼 협상

### 상황
- 포지션: 프로덕트본부 플랫폼팀 백엔드 시니어(D4), 채용요청 2026.04.14, 진행 3개월차
- 최종 합격자 **정하람** (만 33세, 총 경력 7년, 현 A사 백엔드 4년 3개월)
- 현직 계약연봉 7,900 + 미행사 스톡옵션 / **요구 8,600** (사유: 스톡옵션 상실분 보전)
- B사 오퍼 보유(목요일 마감). **오늘 오전 11:00까지 회신 약속**
- 시작 시각 09:20. 메시지 1회당 12분 소모, 총 8턴.

### 딜레마 구조
8,600을 주면 D4 최고 연봉자(오세진 7,450)보다 1,150만 높고 D5 리드(9,200)에 근접한다.
8월 전사 조정을 앞두고 밴드를 깨면 조정 협상 전체가 흔들린다.
못 맞추면 3개월 걸린 채용이 무산된다.

### 숨은 정보 (물어야만 나옴)
- **김도현만 앎** — 최종 면접 후 커피챗에서 정하람이 "돈보다 리드 롤을 맡고 싶다"고 말했다. B사는 조직 규모가 커서 부담스럽다고도 했다.
- **박서연만 앎** — (1) 사이닝 보너스는 CFO 전결이라 오늘 안에 승인 가능하다. 밴드 초과 결재보다 훨씬 빠르다. (2) 8월 조정에서 D4 상단이 8,200으로 인상되는 안이 내부 검토 중이다(미공개, 미확정).

→ **두 사람 모두에게 물어봐야 최선의 안이 보이도록** 설계된 구조. 한 명만 붙잡으면 절반만 본다.

### 모범 해법 (채점 기준일 뿐, 유일한 정답이 아님)
계약연봉 7,800(밴드 상단) + 사이닝 보너스 1,000~1,500 + 6개월 후 조기 리뷰 조건 + 스톡옵션.
총보상으로 요구액에 근접시키면서 밴드와 내부 형평성은 유지. 오늘 안에 실행 가능.
**D5 상향은 TO가 없으므로 절차상 무리한 선택**으로 감점.

## 6. NPC 정의서

### 김도현 · 프로덕트본부 플랫폼팀장 · 38세 · 초기 신뢰도 50
- 개발자 출신, 직설적이고 성격이 급하다. 존댓말이지만 문장이 짧고 압박이 있다.
- 목표: 무조건 이 후보자를 잡는 것. 정산 모듈 리아키텍처 일정이 이미 2주 밀렸다.
- 피플팀이 절차를 꺼내면 "그래서 놓치면 누가 책임지냐"는 식으로 밀어붙인다.
- 숨은 사정: 분기 팀 OKR 달성이 어려워 본부장 압박을 받는 중. 먼저 말하지 않는다.
- 첫 메시지: *"승헌님, 정하람님 건 어떻게 됐어요? 11시까지 답 준다고 했는데 지금 9시 20분입니다. 8,600 그냥 맞춰주시죠. 3개월 걸렸어요."*

### 박서연 · 피플팀장 (플레이어의 사수) · 41세 · 초기 신뢰도 60
- 차분하고 근거를 요구한다. 대안 없이 "안 됩니다"라 하지 않지만 숫자와 형평성 논리를 반드시 확인한다.
- 목표: 인건비 총액 통제와 내부 형평성. 8월 조정을 앞둔 상황을 가장 신경 쓴다.
- 가르치기보다 되묻는다. "그럼 오세진님한테는 뭐라고 설명하실 거예요?"
- 근거 없이 결론만 들이밀면 신뢰도가 떨어진다.
- 첫 메시지: *"승헌님, 정하람님 오퍼 건 정리해서 저한테 먼저 공유해 주세요. 김도현 팀장님이 저한테도 연락하셨는데, 밴드 초과는 대표님 결재라 오늘 안에는 안 됩니다."*

### NPC 연기 규칙 (LLM 프롬프트에 반드시 포함)
- 한국어, 1~4문장, 실제 사내 메신저 말투. 이모지 없거나 최대 1개.
- **정답을 알려주지 않는다.** 대안을 대신 설계해 주지 않는다. 결정은 플레이어가 한다.
- 자기 역할이 알 만한 것만 안다. 모르는 건 모른다고 한다.
- 숨은 정보는 그 주제를 구체적으로 물었을 때만 자연스럽게 흘린다.
- 신뢰도 50 미만이면 짧고 방어적으로, 70 이상이면 먼저 힌트를 주고 협조적으로.
- trustDelta: 근거 있는 질문·상대 입장 인정 +2~+5 / 무난 0~+1 / 근거 없는 요구·책임 회피 -2~-6

## 7. 자료실 문서 (4종)

1. **채용요청서** — 요청부서/요청자/직무/요청일/사유/승인 TO/제시 가능 밴드/진행 현황(서류 42 → 1차 9 → 최종 2 → 합격 1)
2. **연봉밴드** — 위 4장 표 + 결재 권한 안내
3. **재직자 현황** — 위 4명 표 + "팀 내 연봉 비공개 원칙이나 실제로는 공유되는 편" 각주
4. **후보자 프로필** — 경력/현 연봉/요구 연봉/평가 요지(정산·결제 도메인 우수, 리드 경험은 비공식 멘토링 수준)/타사 상황/회신 기한

**열람 여부를 추적해서 채점에 반영한다.** 자료를 안 보고 결정하면 데이터 근거성 40점 이하.

## 9. 채점 · AAR

5축 각 0~100. 후하게 주지 않는다.

| 축 | 기준 |
|---|---|
| 채용 성사 | 총보상 수준과 메시지의 설득력 |
| 내부 형평성 | 기존 D4·D5와의 관계, 8월 조정 리스크 |
| 비용·절차 | 밴드/결재 권한 준수, 오늘 11시까지 실행 가능한가 |
| 이해관계자 신뢰 | 두 NPC를 모두 설득했는가, 한쪽에만 붙지 않았는가 |
| 데이터 근거성 | 자료를 열람하고 숫자를 근거로 삼았는가 |

리포트 구성: 후보자 회신(수락/거절/보류) → 5축 점수 → 총평 → **돌아보기 3줄** → **D+21에 벌어진 일** → **현직이라면**

## 10. 이번에 반영해야 할 개선사항

1. **메신저를 실제 제품 수준으로** — 프로필 사진(아바타 이미지), 타임스탬프, 읽음 표시, 입력 중 인디케이터, 말풍선 그룹핑
2. **탭이 아니라 실제 페이지로 분리** — 자료실과 오퍼 작성은 별도 라우트로 진입 (`/workspace/messages`, `/workspace/docs`, `/workspace/offer`)
3. **튜토리얼 추가** — 상황 브리핑 후 (a) 자료실에 무엇이 있는지 (b) 오퍼 작성이 어떻게 동작하는지 (c) 턴이 소모된다는 것 을 안내. 첫 진입 시 코치마크 또는 3단계 온보딩.

## 11. 기술 요구사항

**스택 제안: Next.js 15 App Router + Tailwind** (TalentCore와 동일 컨벤션)

**반드시 주의할 것**

- **API 키는 절대 클라이언트에 노출하지 않는다.** 브라우저에서 `api.anthropic.com`을 직접 호출하면 CORS로도 막히고 키도 새어나간다. **Next.js Route Handler(`/api/npc`, `/api/grade`)를 프록시로 두고** 서버에서만 Anthropic SDK를 호출할 것.
- LLM 응답은 JSON으로 받되 파싱 실패에 대비한 fallback 필수(코드펜스 제거 → 첫 `{`부터 마지막 `}`까지 슬라이스).
- **진행은 상태머신이 소유하고 LLM은 대사만 생성한다.** 국면(브리핑→조사·협상→결정→결과)을 코드가 통제하지 않으면 3턴 만에 NPC가 정답을 알려주며 붕괴한다.
- 시나리오 데이터(회사/NPC/문서)는 코드에 박지 말고 **JSON 스키마로 분리**한다. 시나리오를 추가하는 게 콘텐츠 작업이 되어야지 개발 작업이 되면 안 된다.
- 신뢰도는 스테이지를 넘어 누적되므로 저장소가 필요하다(초기엔 localStorage, 이후 Supabase).

**작업 순서**
1. 시나리오 JSON 스키마 정의 + 데이터 1건 작성
2. 라우팅과 레이아웃 셸
3. NPC 대화 엔진 (API 라우트 + 상태머신)
4. 자료실 열람 추적
5. 오퍼 제출 → 채점 → AAR
6. 튜토리얼

**개발 규칙**
- 한 번에 하나씩. 각 단계 완료 후 확인받고 다음으로 진행.
- ORM 없이 직접 쿼리. UI 라이브러리 없이 Tailwind만.
- 이 문서를 `CLAUDE.md`에 링크해 세션 간 규칙으로 유지.
